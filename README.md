# ⚡ AMINCK Nova Bot

ربات حرفه‌ای فروش کانفیگ روی **Cloudflare Workers** — کاملاً سرورلس؛ مدیریت کامل **داخل خود تلگرام**.
دیتابیس داخل **Durable Object (SQLite)** است؛ یعنی دیپلوی با **یک کلیک** و بدون ساخت هیچ کلید KV/D1.

> 🤖 فروشگاه خودکار، پنل مدیریت شیشه‌ای، رفرال، مینی‌اپ سکه‌ای، چت هوش مصنوعی، QR برند، تایید فیش با هوش مصنوعی، تبلیغ گروه‌ها و یادآوری تمدید — همه در یک ورکر.

---

## 🚀 دیپلوی با یک کلیک

[![Deploy to Cloudflare Workers](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/amingangmanatgh2-hash/AMINCK-Nova-Edge)

1. روی دکمه بالا بزنید → به گیت‌هاب و کلادفلر وصل شوید → **Deploy**. در کانفیگ پروژه هیچ متغیر `[vars]` یا Secret نمونه‌ای تعریف نشده است، بنابراین فرم متغیرهای ربات و URL نشان داده نمی‌شود.
2. بعد از پایان دیپلوی، آدرس Worker را باز کنید و به `/setup` بروید.
3. توکن BotFather را در صفحه ستاپ وارد کنید. Worker ابتدا آن را با Telegram بررسی می‌کند، سپس وب‌هوک را روی `/webhook` ثبت و توکن را در SQLite داخل Durable Object ذخیره می‌کند.
4. در تلگرام `/start` بزنید — **اولین کاربر سوپرادمین** است و پروفایل بات (نام، توضیحات، دستورها، عکس) خودکار تنظیم می‌شود.

> ℹ️ آدرس Worker از اولین درخواست به‌صورت خودکار در Durable Object ذخیره می‌شود (لینک ساب، QR و مینی‌اپ بدون تنظیم URL اضافی کار می‌کنند).
> صفحه `/setup` فقط راه‌اندازی اولیه را انجام می‌دهد؛ توکن در HTML پاسخ یا لاگ پروژه چاپ نمی‌شود.

### دیپلوی دستی (اختیاری)

```bash
npm install
npx wrangler login
npm run setup     # = wrangler deploy
```

پس از دیپلوی دستی نیز آدرس Worker را باز کنید و `/setup` را اجرا کنید.

### توسعه محلی

برای توسعه محلی یک فایل نادیده‌گرفته‌شده به نام `.dev.vars` بسازید و مقدار توکن محلی را فقط در همان فایل قرار دهید؛ این فایل هرگز commit نمی‌شود:

```bash
touch .dev.vars
$EDITOR .dev.vars
npm run dev
```

## ⚙️ تنظیم توکن و آدرس Worker

- در `wrangler.toml` هیچ `[vars]`ای برای توکن یا URL وجود ندارد؛ Deploy to Cloudflare به‌خاطر این پروژه فیلد متغیر ربات نشان نمی‌دهد.
- مسیر `/setup` توکن را از فرم می‌گیرد، با `getMe` اعتبارسنجی می‌کند، `setWebhook` را صدا می‌زند و سپس مقدار را در جدول `settings` داخل Durable Object ذخیره می‌کند.
- کد در هر درخواست ابتدا `telegram_bot_token` را از Durable Object می‌خواند و فقط اگر وجود نداشت از `env.TELEGRAM_BOT_TOKEN` استفاده می‌کند. متغیر env برای `.dev.vars` در توسعه محلی و نصب‌های قدیمی نگه داشته شده است.
- origin عمومی از اولین درخواست کش می‌شود و نیازی به تنظیم URL دستی نیست.

> 🤖 **هوش مصنوعی هیچ کلید خارجی نمی‌خواهد.** همه‌چیز روی **Workers AI** بومی کلادفلر اجرا می‌شود
> (بایندینگ `[ai]` در `wrangler.toml` — با دیپلوی خودکار فعال می‌شود).
> مدل متن: `@cf/meta/llama-3.1-8b-instruct` | مدل بینایی: `@cf/meta/llama-3.2-11b-vision-instruct`

## 🖥 پنل تحت وب

آدرس: `https://aminck-nova-bot.<زیردامنه-تو>.workers.dev/panel`

- ورود فقط با رمز **دقیقاً ۱۰ رقم عددی** (هم در سمت مرورگر و هم سمت سرور اجبار می‌شود).
- اگر رمزی تنظیم نشده باشد، در اولین اجرا یک رمز ۱۰ رقمی تصادفی ساخته و ذخیره می‌شود.
- دیدن/تغییر رمز از تلگرام: **پنل مدیریت → ⚙️ تنظیمات → 🔐 رمز پنل وب (۱۰ رقم)**

## 🖧 سرورها و تحویل واقعی (بدون کانفیگ نمونه)

از این نسخه به بعد **هیچ کانفیگ نمونه/تصادفی تحویل داده نمی‌شود**:

- سرورهای نمونهٔ `*.example.com` دیگر فعال نیستند و یک **مهاجرت خودکار** (`migration:placeholder_servers_v1`)
  روی نصب‌های قدیمی هم آن‌ها را غیرفعال می‌کند — تغییر seed به‌تنهایی کافی نبود چون فلگ `seeded` از قبل ثبت شده بود.
- اگر هیچ سرور واقعیِ فعالی وجود نداشته باشد، خرید/تحویل با پیام
  «⚠️ هنوز سرور واقعی تنظیم نشده است؛ این محصول فعلاً قابل تحویل نیست.» متوقف می‌شود و **پول کاربر کسر نمی‌شود**.
- صفحهٔ `/sub` هیچ کانفیگ `example.com` یا سرور ناقصی نشان نمی‌دهد.

### افزودن سرور واقعی

از تلگرام: **پنل مدیریت → 🖥 سرورها → ➕ سرور جدید**
(نام → پروتکل → هاست/IP → پورت → secret → قالب → آدرس سلامت → رتبهٔ سرعت)

یا از پنل وب: تب **🖥 سرورها → ➕ سرور جدید**.

> 🩺 **دربارهٔ تست سلامت:** این تست فقط یک درخواست HTTP از شبکهٔ Cloudflare است.
> Workers اجازهٔ ICMP/ping ندارد، بنابراین نتیجهٔ آن **معادل پینگ واقعی از داخل ایران نیست**
> و هیچ ادعایی دربارهٔ کیفیت اتصال از نت ملی نمی‌کند.

## 📡 تحویل MTProto (لینک مستقیم تلگرام)

محصولات MTProto و SOCKS5 دیگر لینک `/sub/<token>` نمی‌گیرند؛ کاربر یک **لینک اتصال مستقیم**
با دکمهٔ «🔗 اتصال مستقیم در تلگرام» دریافت می‌کند:

```
tg://proxy?server=<host>&port=<port>&secret=<secret>
https://t.me/proxy?server=<host>&port=<port>&secret=<secret>
```

- `secret` همان مقدار **ذخیره‌شده در دیتابیس** است؛ هرگز از UUID تصادفی ساخته نمی‌شود.
- سکرت‌های پذیرفته‌شده: ۳۲ کاراکتر هگز، یا `dd`/`ee` + هگز، یا base64url (حداقل ۲۲ کاراکتر).
- اگر host/port/secret ناقص باشد **هیچ لینکی ساخته نمی‌شود**: کاربر پیام «به پشتیبانی ارجاع شد» می‌گیرد
  و ادمین‌ها گزارش دقیق مشکل پیکربندی را دریافت می‌کنند.
- VLESS / VMess / Trojan / Shadowsocks همچنان لینک اشتراک `/sub/<token>` می‌گیرند.

## 🤖 هوش مصنوعی (Workers AI)

**ریشهٔ خرابی قبلی:** مدل `@cf/meta/llama-3.1-8b-instruct` توسط Cloudflare **منسوخ (Deprecated)** شده است،
بنابراین هر فراخوانی شکست می‌خورد و کاربر پیام «دستیار هوشمند فعلاً در دسترس نیست» می‌دید.

اکنون یک **زنجیرهٔ مدل** با fallback استفاده می‌شود:

1. `@cf/meta/llama-3.3-70b-instruct-fp8-fast`
2. `@cf/meta/llama-3.1-8b-instruct-fp8`
3. `@cf/meta/llama-3.2-3b-instruct`

- ادمین می‌تواند از **پنل وب → ⚙️ تنظیمات → مدل Workers AI** مدل دلخواه را انتخاب کند؛ اگر مدلِ انتخابی منسوخ باشد نادیده گرفته می‌شود.
- خطاها تفکیک می‌شوند: `binding_missing` / `model_error` / `quota_exceeded` / `invalid_response` / `disabled`.
- همهٔ شکل‌های پاسخ پارس می‌شوند: `response`، `result.response`، `choices[].message.content` و رشتهٔ خام.
- **در هیچ خطایی سکه کسر نمی‌شود** و به کاربر دکمه‌های «🔁 تلاش دوباره» و «🧑‍💼 اتصال به اپراتور» داده می‌شود.
- دکمهٔ **🧪 تست اتصال هوش مصنوعی** در پنل وب وضعیت binding، مدل پاسخ‌گو، زمان پاسخ و کد خطا را نشان می‌دهد (بدون افشای هیچ توکنی).

## 🎡 گردونهٔ شانس

- `/api/game/spin` با یک **قفل اتمیک** روی ستون `users.spin_claim` کار می‌کند؛
  در چند درخواست هم‌زمان (دابل‌کلیک) فقط یکی برنده می‌شود.
- پاسخ موفق: `{ ok, prize, index, segments, coins, spinDone }` — `index` شمارهٔ برشِ برنده روی گردونه است.
- پاسخ تکراری: `{ ok:false, reason:'already', spinDone:true, coins }`.
- فرانت‌اند: اشاره‌گر ثابت، چرخش رو‌به‌جلو تا مرکز برشِ برنده، پایان با `transitionend`
  (به‌علاوهٔ تایم‌اوت ایمنی ۴٫۶ ثانیه‌ای)، و در خطا دکمه دوباره فعال می‌شود — بدون قفل‌شدن دائمی.

```bash
npm test                    # ۲۶۴ تست روی SQLite واقعی + تلگرام شبیه‌سازی‌شده
```

تست‌ها اقتصاد سکه، شارژ کیف پول، پاداش رفرال، ویزاردهای ادمین، احراز هویت و امنیت پنل وب،

- **۲۱)** ساخت لینک مستقیم MTProto با سکرت ذخیره‌شده + رد کردن هاست نمونه و سکرت جعلی + رگرسیون لینک `/sub` برای VLESS
- **۲۲)** نبودِ `example.com` در خروجی اشتراک و صفحهٔ `/sub` + مهاجرت غیرفعال‌سازی سرورهای نمونه
- **۲۳)** توقف خرید و تحویل وقتی سرور واقعی وجود ندارد (بدون کسر پول)
- **۲۴)** گردونه: چرخش موفق، رد چرخش تکراری، رد چهار درخواست هم‌زمان به‌جز یکی، تطابق `index` با جایزه
- **۲۵)** AI: منسوخ‌نبودن مدل پیش‌فرض، موفقیت، نبود binding، خطای مدل، خطای سهمیه، پاسخ نامعتبر، چهار شکل مختلف پاسخ، عدم کسر سکه
- **۲۶)** ارسال دقیقاً یک لینک اشتراک و جلوگیری از تحویل تکراری
- **۲۷)** امنیت پنل وب: ۴۰۱ برای همهٔ APIها بدون سشن، عدم افشای توکن/رمز/سکرت، مدیریت محصول و سرور، اعتبارسنجی

> ⚠️ **صادقانه:** این تست‌ها همگی محلی و با تلگرام و Workers AI شبیه‌سازی‌شده اجرا می‌شوند.
> پاسخ واقعی مدل‌های Workers AI و تحویل واقعی پیام در تلگرام تنها پس از دیپلوی روی حساب Cloudflare
> و از طریق دکمهٔ «🧪 تست اتصال هوش مصنوعی» در پنل قابل تایید است.
