**نسخهٔ ۲.۱ — ثبت توکن داخل پنل، اتصال خودکار و افزودن گروه با لینک تلگرام.**

این نسخه جایگزین برنامهٔ قبلی مخزن شده است؛ تاریخچهٔ Git و مجوز پروژه حفظ شده‌اند. کد این نسخه روی شاخهٔ `arena/01a07081-aminck-nova-edge` است، نه لزوماً شاخهٔ پیش‌فرض.

## واقعاً چه چیزهایی آماده است؟

- راه‌اندازی آسان: فقط رمز پنل هنگام نصب؛ دریافت توکن در پنل مالک، تأیید با Telegram، ذخیرهٔ رمزگذاری‌شده، ثبت خودکار اتصال، منوی دستورها، آزمایش دریافت پیام، لینک افزودن گروه و بازیابی گروه‌های ازقبل‌عضوشده.

- **۱۳۲ دستور مستقل** با نام فارسی و انگلیسی، با و بدون `/`؛ **۳۵ دستور اختصاصی مالک** زیرمجموعهٔ همین تعداد است.
- **۲۴ فیلتر محتوا**: لینک و لینک مخفی، دعوت، فوروارد، استیکر، عکس، ویدیو، گیف، ویس، فایل اجرایی، مخاطب، موقعیت و…؛ بررسی ویرایش‌ها و کپشن‌ها.
- پنل اینلاین دسته‌بندی‌شدهٔ گروه، اخطار و مجازات، سکوت زمان‌دار، بن، اخراج، سنجاق، ضدسیل پیام، کپچای دکمه‌ای، حالت شب و ضدهجوم.
- لیست سیاهِ **متن دقیق، عبارت و استیکر با شناسهٔ پایدار**؛ مدیر روی پیام ریپلای می‌کند و «دیمن» می‌فرستد.
- پاک‌سازی تأییددار، صف حذف دسته‌ای تا ۱۰۰ شناسه در هر درخواست؛ سقف ۵۰۰۰ پیام ثبت‌شده در هر عملیات.
- **۶ دوئل بومی تلگرام**: 🎲 🎯 🏀 ⚽ 🎳 🎰؛ رزرو شرط، ثبت اولین پرتاب، تسویهٔ اتمی، انصراف پیش از پیوستن، مساوی و برد با عدم حضور حریف.
- پروفایل، سطح، XP فعالیت با محدودیت زمانی، لیدربرد گروهی و سراسری، جایزهٔ سکهٔ روزانه و الماس کمیاب.
- پیام و پین از طرف بات، زمان‌بندی یک‌باره، یادداشت گروه، پاسخ خودکار دقیق، خوش‌آمد و خروج با قالب، قوانین، شوخی/حقیقت/جرئت دوستانه، ساعت و ماشین حساب بدون `eval`.
- پنل وب فارسی واکنش‌گرا، پوستهٔ تیره/روشن، مدیریت واقعی گروه‌ها، کیف پول، گزارش و صف، کتابخانهٔ جست‌وجوپذیر دستورها، تنظیم وبهوک و خروجی تنظیمات.
- کنسول مالک در ترموکس با منوی تعاملی؛ ارسال به گروه، ارسال و پین، قفل‌ها، پاک‌سازی، اعتبار و زمان‌بندی.
- سلف اختیاری با **۱۷ فرمان محلی**؛ ورود فقط به حساب خود کاربر روی دستگاه او، نه در بات یا وب‌سایت.

فهرست کامل و تولیدشده از کد: **[قابلیت‌ها و دستورها](docs/FEATURES.fa.md)**.

**این نسخه ادعای «۴۰۰+» یا «۱۰۰۰+ قابلیت مستقل» ندارد.** اسم‌های مترادف، حالت روشن/خاموش، بازی‌ها و دکمه‌ها را چندبار نمی‌شماریم. سخنگوی فعلی پاسخ‌های آماده و دوستانه دارد، نه یک مدل زبانی متصل به سرویس AI.

## نصب روی کلودفلر — فقط یک رمز، بعد توکن داخل پنل

راهنمای کوتاه و رفع مشکل «پنل جواب نمی‌دهد»: **[راه‌اندازی ساده](docs/SETUP.fa.md)**.

### ۱. نصب و ثبت بات

1. دکمهٔ **Deploy to Cloudflare** بالای این صفحه را باز کنید.
2. هنگام نصب فقط **`PANEL_PASSWORD`** را تعیین کنید: یک رمز دلخواه، یکتا و حداقل ۱۶ کاراکتری برای ورود پنل. این رمز، توکن بات نیست. هیچ توکن API کلودفلر لازم نیست.
3. Deploy را تمام کنید و **آدرس ورکر نصب‌شدهٔ خودتان** را باز کنید. با همان رمز وارد شوید.
4. صفحهٔ **ثبت و اتصال بات** باز می‌شود. **توکن تازهٔ BotFather را داخل پنل** بچسبانید و تأیید کنید که اتصال همین بات به این پنل تنظیم شود.
5. **تأیید توکن و اتصال خودکار بات** را بزنید. پنل توکن را با `getMe` بررسی، رمزگذاری و ذخیره می‌کند، کلید داخلی لازم را خودکار می‌سازد، وبهوک را ثبت و منوی دستورها را نصب می‌کند.
6. **آزمایش در تلگرام** را بزنید و در خصوصی بات Start کنید. تا وقتی واقعاً آپدیت نرسیده، پنل فقط «منتظر آزمایش پیام» نشان می‌دهد؛ ثبت وبهوک را به‌دروغ دریافت پیام حساب نمی‌کند.
7. **انتخاب گروه و افزودن بات در تلگرام** را بزنید. گروه خصوصی هم با انتخاب خودتان در تلگرام قابل اضافه‌شدن است.
8. بات را ادمین کنید و داخل گروه `/panel` یا دستور دقیق `/panel@نام‌بات` نمایش‌داده‌شده در پنل را بفرستید. بعد از اتصال درست، «پنل» فارسی هم کار می‌کند.

برای Build از `npm run build` و Deploy از `npm run deploy` استفاده کنید؛ Node.js نسخهٔ ۲۲ یا جدیدتر. Durable Object مبتنی بر SQLite خودکار از migration ساخته می‌شود؛ D1، KV یا Cron جدا لازم نیست. هزینه و سهمیه تابع حساب Cloudflare است.

**اگر نسخهٔ ۲.۰ نصب است، ابتدا کد همان ورکر را به ۲.۱ به‌روزرسانی و Deploy کنید؛ Refresh مرورگر کد سرور را ارتقا نمی‌دهد.** نصب با نام ورکر جدید، فضای دادهٔ جدید می‌سازد؛ برای نگه‌داشتن کیف پول و تنظیمات، همان ورکر و binding ذخیره‌سازی را ارتقا دهید. لینک نصب تازه هم در ابتدای README موجود است.

### توکن کجا نگه‌داری می‌شود؟

- فقط مالک واردشده، روی HTTPS و با درخواست هم‌مبدأ می‌تواند آن را ثبت کند.
- توکن و کلید وبهوک با **AES-GCM** و کلید مشتق‌شده از `PANEL_PASSWORD`، با salt و nonce تصادفی، در فضای ذخیره‌سازی همین ورکر نگه‌داری می‌شوند.
- توکن در پاسخ API، بکاپ تنظیمات، گزارش، URL، کد گیت یا localStorage مرورگر برگردانده/ثبت نمی‌شود. ورودی فرم بعد از ارسال پاک می‌شود.
- **اگر رمز پنل را در Cloudflare عوض کنید، توکن همان بات را یک‌بار دوباره در پنل ثبت کنید.** نشست‌های وب قبلی با تغییر رمز باطل می‌شوند؛ اطلاعات رمزگذاری‌شده هم تا ثبت مجدد قابل خواندن نیست.
- نصب‌های قبلی دارای `BOT_TOKEN` و `WEBHOOK_SECRET` همچنان پشتیبانی می‌شوند. پس از ثبت از پنل، مقدار رمزگذاری‌شده بر تنظیم قدیمی اولویت دارد؛ نیازی به پاک‌کردن Secrets قدیمی نیست.
- هر نصب به یک بات متصل می‌شود. تعویض توکن همان بات مجاز است؛ برای بات با شناسهٔ متفاوت یک نصب جدا بسازید تا گروه‌ها و اقتصاد دو بات مخلوط نشوند.
- **شماره، کد ورود، رمز دومرحله‌ای، API hash حساب شخصی یا session را اینجا وارد نکنید.** فرم فقط توکن Bot API می‌گیرد.

### دسترسی‌ها؛ ندادن Ban Users نباید پنل را خاموش کند

| قابلیت | دسترسی لازم برای بات |
|---|---|
| پاسخ به `/panel` و بازی‌های معمول | عضویت و اجازهٔ ارسال/دریافت پیام؛ Ban لازم نیست |
| دیدن «پنل» فارسی و همهٔ پیام‌های گروه | ادمین‌بودن بات یا خاموش‌بودن Group Privacy در BotFather |
| حذف پیام، پاک‌سازی، لیست سیاه | Delete Messages |
| بن، سکوت، کپچا و ضدهجوم | Ban / Restrict Users؛ محدودکردن عضو در سوپرگروه |
| سنجاق پیام | Pin Messages |
| تغییر عنوان/توضیح | Change Group Info |
| مدیریت دعوت و درخواست عضویت | Invite Users |

مدیر واقعی گروه یا یکی از دو مالک سراسری می‌تواند پنل را استفاده کند؛ عضو عادی نمی‌تواند با دکمه‌ها دسترسی بگیرد. **مدیر ناشناس باید برای فرمان مدیریتی از حالت ناشناس خارج شود.** مالک‌بودن در کد، حق‌های واقعی Telegram را دور نمی‌زند.

در صفحهٔ گروه‌ها، **بررسی دسترسی بات** وضعیت واقعی را از تلگرام می‌گیرد و کمبود حق بن را جدا از توانایی بازشدن پنل نشان می‌دهد. در نبود حق Restrict، ورود اعضا و خوش‌آمد متوقف نمی‌شود؛ قابلیت نیازمند آن حق رد و توضیح داده می‌شود.

### بات از قبل عضو است، ولی گروه در پنل دیده نمی‌شود

وجود بات در گروه به‌تنهایی ثابت نمی‌کند وبهوک به **همین ورکر** متصل است. پنل جدید آدرس فعلی و مورد انتظار را مقایسه می‌کند و اگر پیام‌ها به جای دیگری می‌روند، **اتصال بات به همین پنل / تعمیر اتصال** را پیشنهاد می‌دهد.

- اول اتصال را کامل کنید؛ بعد در همان گروه `/panel@نام‌بات` بفرستید یا از لینک «انتخاب گروه و افزودن بات» همان گروه را انتخاب کنید.
- در «افزودن گروه»، گزینهٔ **بات از قبل عضو گروه است، ولی اینجا دیده نمی‌شود** را باز کنید و لینک عمومی `https://t.me/groupname`، `@groupname` یا شناسهٔ عددی منفی گروه را بدهید. سرور عضویت واقعی بات را بررسی و سپس گروه را ثبت می‌کند.
- **بات نمی‌تواند با لینک دعوت خصوصی `t.me/+…` خودش عضو شود.** برای گروه خصوصی از انتخاب‌گر رسمی تلگرام استفاده کنید؛ ثبت لینک در پنل عضویت خودکار یا دورزدن دعوت نیست.
- وقتی از تلگرام به پنل برمی‌گردید، بررسی کوتاه‌مدت اتصال/گروه‌ها خودکار انجام می‌شود؛ دکمهٔ بررسی دوباره هم هست.

## شروع سریع در گروه

همهٔ نمونه‌ها شکل انگلیسی با `/` هم دارند. فارسی با `/` و انگلیسی بدون `/` هم قابل استفاده‌اند.

```text
پنل
راهنما
راهنما security
قفل لینک
بازکردن استیکر
ضداسپم روشن
حد اسپم ۶
حد اخطار ۳
کپچا روشن
خوشامد سلام {name}، به {group} خوش اومدی!
تنظیم قوانین احترام، رفاقت و بدون تبلیغات.
شب ۰ ۷
شب خاموش
دوئل 🎲 ۵۰
لیدربرد
لیدربرد xp
روزانه
```

روی پیام عضو ریپلای کنید:

```text
اخطار
سکوت ۳۰
بن
رفع سکوت
پاک
پین
دیمن
رفع دیمن
```

بدون ریپلای، شناسهٔ عددی را بعد از دستور قرار دهید؛ مثال: `/mute 123456 30`. اگر روی پیام ریپلای کرده‌اید، هدف همان فرستنده است. پیام ناشناس و کانال، هویت قابل‌اعتماد برای فرمان مدیریتی محسوب نمی‌شود.

### پیام از طرف بات و سنجاق

دو مالک اصلی، در هر گروه ثبت‌شده می‌توانند بنویسند:

```text
پیام درخواست دسترسی کامل لطفا ؛پین
```

بات متن «درخواست دسترسی کامل لطفا» را می‌فرستد و در صورت داشتن دسترسی Pin آن را سنجاق می‌کند. **این فقط ارسال درخواست است و به کسی خودکار دسترسی ادمین نمی‌دهد.**

از خصوصی بات، برای گروه مقصد:

```text
ارسال -1001234567890 سلام رفقا
ارسال پین -1001234567890 درخواست دسترسی کامل لطفا
```

همین دو کار در پنل وب و ترموکس هم وجود دارد. اگر ارسال موفق و پین ناموفق باشد، پاسخ این تفاوت را مشخص می‌کند؛ برای جلوگیری از ارسال تکراری، دوباره کل فرمان را نفرستید.

### لیست سیاه

- روی **متن** ریپلای + «دیمن»: همان متن نرمال‌شدهٔ دقیق مسدود می‌شود؛ تفاوت حروف عربی/فارسی و فاصله‌های نامرئی کنار گذاشته می‌شود.
- روی **استیکر** ریپلای + «دیمن»: `file_unique_id` آن مسدود می‌شود، نه `file_id` موقت.
- `کلمه ممنوع عبارت`: هر پیام یا کپشن شامل آن عبارت حذف می‌شود؛ تطبیق ساده است، regex دلخواه اجرا نمی‌شود.
- `رفع دیمن` با ریپلای و `حذف کلمه عبارت`: آزادسازی.
- مدیرهای تلگرام، دو مالک اصلی و معتمدهای آن گروه از فیلترها معاف‌اند. معتمدبودن مجوز مدیریتی نیست.
- سقف فعلی هر گروه: ۳۰۰ مورد لیست سیاه، ۱۰۰ یادداشت و ۱۰۰ پاسخ خودکار.

### پاک‌سازی و «حذف ۱۰۰۰»

```text
پاکسازی
حذف ۱۰۰۰
/purge 1000
```

1. بات فقط **قدیمی‌ترین پیام‌های ثبت‌شدهٔ قابل‌حذف** را انتخاب می‌کند؛ «۱۰۰۰» یعنی حداکثر هزار پیام از این فهرست، نه هزار پیام اول کل تاریخچهٔ تلگرام.
2. تعداد و هشدار نمایش داده می‌شود. فقط درخواست‌کننده تا ۹۰ ثانیه می‌تواند تأیید کند.
3. کار در صف، در دسته‌های حداکثر ۱۰۰تایی و با فاصله اجرا می‌شود؛ برای حذف ۱۰۰۰تایی لازم نیست درخواست HTTP طولانی باز بماند.
4. مجوز درخواست‌کننده در زمان اجرای هر بخش دوباره بررسی می‌شود.
5. Bot API معمولاً حذف را به **کمتر از ۴۸ ساعت** محدود می‌کند؛ پروژه برای رسیدن درخواست، دو دقیقه حاشیهٔ امن می‌گذارد. برخی پیام‌های سرویس هم قابل حذف نیستند.
6. بات API خواندن کل تاریخچه ندارد، پیام‌های قبل از حضورش را نمی‌شناسد و پیام بات‌های دیگر را دریافت نمی‌کند. بنابراین «پاک‌کردن مطلق کل تاریخچه» با Bot API قابل تضمین نیست.
7. `deleteMessages` ممکن است شناسه‌های ناموجود را نادیده بگیرد؛ گزارش ما **شناسه‌های پردازش‌شده** است، نه ادعای تعداد قطعی پیام‌های حذف‌شده. شکست مکرر API در گزارش ثبت می‌شود.

## دوئل، سکه و الماس

- هر کاربر دیده‌شده با ۱۰۰۰ سکه شروع می‌کند؛ جایزهٔ پیش‌فرض روزانه ۱۰۰ سکه، هر **۲۴ ساعت متوالی** است.
- شرط دوئل با **سکهٔ مجازی** است. ارز واقعی، رمزارز، درگاه پرداخت، خرید/فروش اعتبار یا برداشت پول در پروژه وجود ندارد.
- سازنده شرط را رزرو می‌کند؛ حریف دکمه را می‌زند و شرط او هم رزرو می‌شود. فقط یک دوئل فعال برای هر کاربر در کل ربات مجاز است.
- هر دو نفر باید **روی همان پیام چالش بات** ریپلای و ایموجی بازی را ارسال کنند. از متن «۶»، پیام فورواردی، پرتاب تکراری یا تاس شخص سوم امتیاز نمی‌گیریم.
- امتیاز بیشتر، مجموع شرط‌ها را می‌برد. مساوی یا عدم پرتاب هر دو، استرداد است. اگر فقط یک نفر پرتاب کند، پایان مهلت **برد به‌علت عدم حضور حریف** است؛ این مانع فرار از باخت می‌شود.
- انصراف فقط توسط سازنده و **پیش از پیوستن حریف** ممکن است. مهلت پیش‌فرض ساخت و مرحلهٔ فعال هرکدام ۵ دقیقه است.
- اسلات: ۷۷۷ برابر ۱۰۰ امتیاز، سه نماد یکسان ۳۰، یک جفت ۱۰ و بقیه صفر. بقیهٔ بازی‌ها با مقدار بومی Telegram مقایسه می‌شوند.
- برد واقعی با شرط حداقل ۵۰ سکه، در **اولین بازی با آن حریف طی ۲۴ ساعت**، به‌صورت پیش‌فرض شانس **۱ در ۵۰** برای **۱ الماس** دارد. سقف دریافت هر فرد یک الماس در ۲۴ ساعت است. برد با عدم حضور حریف الماس ندارد.
- اعداد تصادفی پاداش با Web Crypto و نمونه‌گیری بدون سوگیری modulo ساخته می‌شوند. تاس را خود Telegram تولید می‌کند؛ بات مقدارش را انتخاب نمی‌کند.
- XP پیام حداکثر هر دقیقه یک بار؛ برد ۲۰ و باخت ۵ XP اضافه می‌کند. امتیاز، برد و باخت گروه از کیف پول سراسری جدا است.
- این کنترل‌ها جلوی بخشی از تکرار و تبانی ساده را می‌گیرند؛ **مقاومت کامل در برابر چندحسابی یا تبانی ادعا نمی‌شود**.

## مالک‌های اصلی

```text
8882866473
7856615968
```

این شناسه‌ها در کد ثابت‌اند، با متن پیام یا پارامتر مرورگر قابل جعل نیستند و همیشه **الماس نامحدود** دارند. Telegram باید هویت واقعی را در آپدیت معتبر ارائه کند.

۳۵ دستور اختصاصی مالک در `راهنمای اونر` / `/ownerhelp` و [فهرست قابلیت‌ها](docs/FEATURES.fa.md) آمده است؛ از جمله ارسال بین‌گروهی، اعتباردادن، توقیف بازی/سلف، تنظیم قواعد اقتصاد، نام/بیو/دربارهٔ بات، نصب منو، ابطال مجوز، گزارش، خروجی و کنترل گروه‌ها. روی کاربرِ هنوز دیده‌نشده نمی‌توان اعتبار واریز کرد؛ ابتدا باید بات را شروع کند یا در گروه پیام بدهد.

ورود وب با رمز مشترک مالک انجام می‌شود و به شناسهٔ اول منتسب است؛ هر دو حساب در تلگرام و ترموکس، شناسهٔ مستقل خودشان را در گزارش دارند.

## ترموکس و سلف محلی

راهنمای کامل: **[نصب ترموکس و حساب شخصی](docs/TERMUX.fa.md)**.

```bash
pkg update && pkg install python git
git clone --branch arena/01a07081-aminck-nova-edge --single-branch \
  https://github.com/amingangmanatgh2-hash/AMINCK-Nova-Edge.git nova-guard
cd nova-guard
python termux/console.py
```

در خصوصی بات، با حساب مالک «ترموکس» بفرستید. کد اتصال یک‌بارمصرف را **در ابزار محلی** وارد کنید. منوی ارسال، پین، قفل، پاک‌سازی، اعتبار و زمان‌بندی آماده است. نیازی به BOT_TOKEN در ترموکس نیست.

سلف برای حساب خود کاربر، اختیاری و جدا است:

```bash
pip install -r termux/requirements.txt
python termux/self_client.py
```

- API ID و API HASH را خودتان از `my.telegram.org` دریافت کنید. ورود با شماره، کد Telegram و در صورت نیاز رمز دومرحله‌ای، فقط روی دستگاه خودتان انجام می‌شود.
- در خصوصی بات، با **همان حساب** «سلف» بفرستید. کد اتصال نُوا را با کد ورود تلگرام اشتباه نگیرید.
- هزینهٔ هر ساعت شروع‌شده **۵ الماس**، پیش‌پرداخت و بدون بازپرداخت ساعت ناقص است. برای دو مالک هزینه‌ای کسر نمی‌شود.
- برنامه پس از تأیید `YES`، هنگام بازبودن هر ساعت تمدید می‌کند؛ هر ۶۰ ثانیه اعتبار و ابطال را بررسی می‌کند. سرور بدون درخواست کلاینت، خودبه‌خود از حساب کسر نمی‌کند.
- توقف عادی با Ctrl+C اعتبار باقیماندهٔ همان ساعت را نگه می‌دارد. «توقف سلف» در بات، مجوز و اجاره را باطل می‌کند و نشست محلی Telegram را حذف نمی‌کند.
- کلودفلر **سلف MTProto را اجرا نمی‌کند**؛ دستگاه/ترموکس باید روشن و آنلاین بماند. محدودیت‌های پس‌زمینهٔ Android ممکن است اجرای برنامه را متوقف کنند.
- سلف از پیام خروجی صاحب حساب فرمان می‌گیرد؛ جمع‌آوری اعضا، ارسال انبوه، دریافت کد دیگران و ابزار آزار ندارد.
- کلاینت متن‌باز است؛ کنترل اجاره، DRM غیرقابل‌دورزدن نیست. حسابداری الماس و API مالک روی سرور محافظت می‌شوند، ولی صاحب یک کلاینت تغییریافته می‌تواند کد محلی را تغییر دهد.

## پیش‌نمایش، توسعه و آزمون

```bash
npm ci
npm run catalog
npm run check
npm run check:termux
npm test
npm run dry-run
npm run dev:demo
```

- پیش‌نمایش روی `0.0.0.0:8787` باز می‌شود. **تمام داده‌های آن نمونه‌اند**؛ هیچ فرمانی به Telegram ارسال نمی‌کند و سرور تغییرات را با 409 رد می‌کند.
- فقط برای توسعه می‌توانید `DEMO_MODE=true` بدهید. در Deploy واقعی **این متغیر را حذف کنید**؛ حالت پیش‌نمایش حتی وبهوک را نمی‌پذیرد.
- بدون رمز پنل معتبر، ورود مالک بسته می‌ماند؛ تا ثبت توکن، وبهوک نیز بسته است؛ هیچ رمز پیش‌فرض یا دورزدن احراز هویت ندارد.
- برای توسعه با بات آزمایشی: `.dev.vars.example` را به `.dev.vars` کپی کنید، رمز پنل را **محلی** جایگزین و `npm run dev` اجرا کنید. Telegram به localhost دسترسی ندارد؛ وبهوک نیازمند دامنهٔ HTTPS عمومی است.
- تست‌ها شامل parser دوزبانه، SQLite واقعی، اتمی‌بودن اقتصاد، تسویه، فورفیت، محدودیت پاداش، مجوزها، کپچا، پاک‌سازی ۱۰۰۰تایی و اجرای واقعی Worker در Miniflare هستند. Telegram در تست‌ها mock است؛ این‌ها جای آزمون در یک گروه آزمایشی واقعی را نمی‌گیرند.
- راهنمای QA مرورگر و مرزهای مقیاس در [معماری](docs/ARCHITECTURE.md) آمده است.

### CI اختیاری

قالب آماده در `docs/ci.yml.example` است. اتصال فعلی GitHub App مجوز ویرایش `workflows` ندارد، بنابراین این نسخه عمداً workflow فعال ایجاد نمی‌کند. تست‌ها در محیط توسعه اجرا شده‌اند، نه در GitHub Actions. اگر CI خودکار می‌خواهید، اتصال GitHub در Arena را با مجوز لازم دوباره برقرار کنید یا با حساب مجاز خودتان قالب را به `.github/workflows/ci.yml` منتقل کنید. هیچ credential در قالب وجود ندارد و استقرار زنده انجام نمی‌دهد.
