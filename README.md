# ⚡ AMINCK Nova Bot

ربات حرفه‌ای فروش کانفیگ روی **Cloudflare Workers** — کاملاً سرورلس؛ مدیریت کامل **داخل خود تلگرام**.
دیتابیس داخل **Durable Object (SQLite)** است؛ یعنی دیپلوی با **یک کلیک** و بدون ساخت هیچ کلید KV/D1.

> 🤖 فروشگاه خودکار، پنل مدیریت شیشه‌ای، رفرال، مینی‌اپ سکه‌ای، چت هوش مصنوعی، QR برند، تایید فیش با هوش مصنوعی، تبلیغ گروه‌ها و یادآوری تمدید — همه در یک ورکر.

---

## 🚀 دیپلوی با یک کلیک

[![Deploy to Cloudflare Workers](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/amingangmanatgh2-hash/AMINCK-Nova-Edge)

1. روی دکمه بالا بزنید → به گیت‌هاب و کلادفلر وصل شوید → **Deploy**. در کانفیگ پروژه هیچ متغیر `[vars]` یا Secret نمونه‌ای تعریف نشده است، بنابراین فرم متغیرهای ربات و URL نشان داده نمی‌شود.
2. بعد از پایان دیپلوی، آدرس Worker را باز کنید و به `/setup` بروید.
3. توکن BotFather را در صفحهٔ `/setup` وارد کنید. اگر بخواهید **رمز ۱۰ رقمی پنل مدیریت** و **آیدی عددی تلگرام مالک** را همان‌جا می‌نویسید؛ اگر رمز را خالی بگذارید، یک رمز ۱۰ رقمی **تصادفی** ساخته می‌شود و فقط یک‌بار در همان صفحه نشان داده می‌شود (چیزی از شما پرسیده نمی‌شود و هیچ‌چیز در کد پروژه ذخیره نمی‌شود).
   Worker ابتدا توکن را با Telegram بررسی می‌کند، سپس وب‌هوک را روی `/webhook` ثبت می‌کند و توکن را در SQLite داخل Durable Object خودش نگه می‌دارد.
4. در تلگرام `/start` بزنید:
   • اگر آیدی مالک را در `/setup` نوشته‌اید، همان کاربر مستقیماً سوپرادمین می‌شود.
   • در غیر این صورت **اولین کاربر باید همان رمز ۱۰ رقمی پنل را وارد کند** تا مالک ثبت شود (۵ تلاش، سپس ۱۵ دقیقه قفل). تا آن لحظه هیچ‌کس — حتی اولین کاربر — نقش ادمین نمی‌گیرد. بعد از ثبت مالک، قفل ادمین خودکار بسته می‌شود.
5. پروفایل بات (نام، توضیحات، دستورها، لوگو) و **دکمهٔ مربعی «🪟 داشبورد»** در منوی پیوست تلگرام خودکار تنظیم می‌شوند.

> ℹ️ آدرس Worker از اولین درخواست به‌صورت خودکار در Durable Object ذخیره می‌شود (لینک ساب، QR و مینی‌اپ بدون تنظیم URL اضافی کار می‌کنند).
> صفحه `/setup` فقط راه‌اندازی اولیه را انجام می‌دهد؛ توکن در HTML پاسخ یا لاگ پروژه چاپ نمی‌شود.

### دیپلوی دستی (اختیاری)

```bash
npm install
npx wrangler login
npm run setup     # = wrangler deploy
```

پس از دیپلوی دستی نیز آدرس Worker را باز کنید و `/setup` را اجرا کنید.

### توسعه محلی

برای توسعه محلی یک فایل نادیده‌گرفته‌شده به نام `.dev.vars` بسازید و مقدار توکن محلی را فقط در همان فایل قرار دهید؛ این فایل هرگز commit نمی‌شود:

```bash
touch .dev.vars
$EDITOR .dev.vars
npm run dev
```

## 🛡 چرا «تضمین ۱۰۰٪» ممکن نیست و ما به‌جایش چه کردیم

> ⚠️ **محدودیت‌های صادقانه این نسخه:**
> • درگاه بانکی فقط یک **درایور** است؛ برای پرداخت آنلاین باید اکانت/مرچنت‌آیدی خودتان را از کارگزاری بگیرید. بدون آن، خرید با کارت‌به‌کارت و تایید فیش کار می‌کند.
> • بررسی سلامت مسیرها از سرور Cloudflare (خارج ایران) انجام می‌شود و فقط **سیگنال نسبی** است؛ تشخیص واقعی فیلترینگ روی اینترنت ایران، از گزارش خود کاربرها (دکمه‌های ✔/✖ در صفحهٔ اشتراک و پروب مینی‌اپ) می‌آید.
> • نرخ طلا/تتر از چند منبع میانه‌گیری می‌شود؛ اگر هیچ منبعی جواب ندهد، قیمت **صفر** و خرید **بسته** می‌ماند و عدد ساختگی نمایش داده نمی‌شود (می‌توانید نرخ دستی تنظیم کنید).
> • Cloudflare Workers دسترسی TCP/ICMP خام ندارد؛ به همین دلیل «پینگ واقعی سرور» از سمت ورکر ممکن نیست و از پروب HTTP/کاربری استفاده شده است.
> • هیچ سرور، کلید Reality یا سکرت MTProto نمونه‌ای تحویل نمی‌شود؛ تا وقتی سرور واقعی ثبت نکنید، فروش کانفیگ متوقف است (kill-switch).

هیچ سرویسی نمی‌تواند اتصال همیشگی روی شبکه‌ای که بخش‌هایی از آن در حال مسدودسازی و
تغییر مداوم است را **تضمین** کند — نه ما و نه هیچ‌کس دیگر. ادعای تضمین، فقط دروغ است.
به‌جای یک وعدهٔ غیرقابل‌اجرا، معماری را «چندلایه و همیشه‌روشن» چیده‌ایم تا وقتی یک
مسیر مرد، مسیر بعدی خودش کار را بگیرد و کاربر فقط ساب را رفرش کند:

| # | لایه | وضعیت در این ریپو |
|---|---|---|
| ۱ | **چند ترنسپورت هم‌زمان** (WebSocket+TLS → gRPC → XHTTP/SplitHTTP → HTTPUpgrade → Reality) | زیرساخت قالب‌ها و ستون‌های سرور آماده است؛ قالب‌های کامل چند-ترنسپورتی هنوز پیاده‌سازی نشده‌اند |
| ۲ | **چند IP تمیز برای هر کانفیگ** مرتب‌شده بر اساس امتیاز واقعی | ✅ هر سرور تا ۴ کانفیگ (clean_ip اختصاصی → IPهای تمیز برتر → خود سرور) می‌سازد |
| ۳ | **ساب پویا** — هر fetch بر اساس امتیاز لحظه‌ای و سلامت سرورها | ✅ `/sub` در هر fetch سرورهای سالم و IPهای تمیز را دوباره می‌سنجد و rebuild می‌کند |
| ۴ | **خود-ترمیمی در کرون** | ✅ سلامت سرورها + جایگزینی خودکار (موجود) + مدارشکن و بازگردانی IPهای بد (جدید) |
| ۵ | **Circuit Breaker** | ✅ برای IPهای تمیز (۵ شکست پیاپی → خروج موقت ۱ ساعته + بازگشت خودکار) |
| ۶ | **Kill-switch محصول** | ✅ خودکار (بدون مسیر سالم فروش/تحویل متوقف) + دستی از پنل (روشن/خاموش/خودکار) + استخراج IP از تأیید اتصال کاربر |

> ⚠️ **صادقانه:** اگر **همهٔ** لایه‌ها هم‌زمان بمیرند (مثلاً کل رنج IP مسدود شود و همهٔ
> سرورها قطع شوند)، هیچ لایه‌ای نمی‌تواند اتصال را برگرداند — در آن حالت سیستم باید
> صادقانه «سرویس در دسترس نیست» بگوید و تحویل کانفیگ مرده را متوقف کند (Kill-switch)،
> نه اینکه کانفیگ خراب تحویل دهد. این رفتار «نگفتن دروغ» در کل ربات رعایت شده است.

## 🌐 مخزن IP تمیز و پروب واقعی از داخل ایران

**نکتهٔ کلیدی:** Worker داخل دیتاسنتر خارج از ایران اجرا می‌شود، پس هر تستی که خود
Worker انجام دهد هیچ ربطی به کیفیت اتصال از نت ملی ندارد و ICMP/ping روی Workers
وجود ندارد. تنها جایی که کد ما داخل ایران اجرا می‌شود، **مینی‌اپ تلگرام روی گوشی کاربر**
است. بنابراین:

- `GET /api/probe/targets` → چند IP کاندید (چرخشی، وزن‌دار)
- کاربر در مینی‌اپ با درخواست کوچک و timeout کوتاه، زمان رسیدن به هر IP را می‌سنجد
- `POST /api/probe/report` با `initData` معتبر → ثبت نتیجه + امتیاز + سکهٔ انگیزشی
- امتیازدهی: میانگین متحرک نمایی + نرخ موفقیت + جریمهٔ شکست پیاپی + وزن تعداد نمونه
- ضدتقلب: سقف روزانه، تشخیص گزارش تکراری، حذف مقادیر پرت با IQR، حداقل نمونه
- تفکیک اپراتور (همراه اول/ایرانسل/مخابرات/رایتل) از گزارش کاربر گرفته می‌شود

> ⚠️ **محدودیت دقیق پروب:** پروب مرورگر/وب‌اپ به‌خاطر CORS معمولاً نمی‌تواند به هر
> دامنه‌ای درخواست واقعی بزند و فقط «تاخیر رسیدن به آن IP از شبکهٔ اپراتور کاربر»
> را تقریب می‌زند — نه توان عملیاتی کامل کانفیگ را. امتیازها صرفاً یک سیگنال نسبی
> برای رتبه‌بندی IPها هستند. کل این قابلیت با کلید `probe_enabled` (پیش‌فرض خاموش)
> توسط ادمین فعال می‌شود.

## 🖧 سرورها و تحویل واقعی (بدون کانفیگ نمونه)

از این نسخه به بعد **هیچ کانفیگ نمونه/تصادفی تحویل داده نمی‌شود**:

- سرورهای نمونهٔ `*.example.com` دیگر فعال نیستند و یک **مهاجرت خودکار** (`migration:placeholder_servers_v1`)
  روی نصب‌های قدیمی هم آن‌ها را غیرفعال می‌کند — تغییر seed به‌تنهایی کافی نبود چون فلگ `seeded` از قبل ثبت شده بود.
- اگر هیچ سرور واقعیِ فعالی وجود نداشته باشد، خرید/تحویل با پیام
  «⚠️ هنوز سرور واقعی تنظیم نشده است؛ این محصول فعلاً قابل تحویل نیست.» متوقف می‌شود و **پول کاربر کسر نمی‌شود**.
- صفحهٔ `/sub` هیچ کانفیگ `example.com` یا سرور ناقصی نشان نمی‌دهد.

### افزودن سرور واقعی

از تلگرام: **پنل مدیریت → 🖥 سرورها → ➕ سرور جدید**
(نام → پروتکل → هاست/IP → پورت → secret → قالب → آدرس سلامت → رتبهٔ سرعت)

یا از پنل وب: تب **🖥 سرورها → ➕ سرور جدید**.

> 🩺 **دربارهٔ تست سلامت:** این تست فقط یک درخواست HTTP از شبکهٔ Cloudflare است.
> Workers اجازهٔ ICMP/ping ندارد، بنابراین نتیجهٔ آن **معادل پینگ واقعی از داخل ایران نیست**
> و هیچ ادعایی دربارهٔ کیفیت اتصال از نت ملی نمی‌کند.

## 📡 تحویل MTProto (لینک مستقیم تلگرام)

محصولات MTProto و SOCKS5 دیگر لینک `/sub/<token>` نمی‌گیرند؛ کاربر یک **لینک اتصال مستقیم**
با دکمهٔ «🔗 اتصال مستقیم در تلگرام» دریافت می‌کند:

```
tg://proxy?server=<host>&port=<port>&secret=<secret>
https://t.me/proxy?server=<host>&port=<port>&secret=<secret>
```

- `secret` همان مقدار **ذخیره‌شده در دیتابیس** است؛ هرگز از UUID تصادفی ساخته نمی‌شود.
- سکرت‌های پذیرفته‌شده: ۳۲ کاراکتر هگز، یا `dd`/`ee` + هگز، یا base64url (حداقل ۲۲ کاراکتر).
- اگر host/port/secret ناقص باشد **هیچ لینکی ساخته نمی‌شود**: کاربر پیام «به پشتیبانی ارجاع شد» می‌گیرد
  و ادمین‌ها گزارش دقیق مشکل پیکربندی را دریافت می‌کنند.
- VLESS / VMess / Trojan / Shadowsocks همچنان لینک اشتراک `/sub/<token>` می‌گیرند.

## 🧪 نسخهٔ شیشه‌ای، پنج‌زبانه و فروش در گروه

### 🌐 زبان در اولین `/start`
- کاربر در **اولین `/start`** زبان را از منوی شیشه‌ای انتخاب می‌کند: **فارسی، English، العربية، Русский، Türkçe** — پنل مدیریت عمداً فارسی می‌ماند.
- کل کیبورد اصلی، متن‌ها و برچسب دکمه‌ها از `users.lang` بومی می‌شوند؛ اگر کاربر دکمهٔ سفارشیِ ترجمه‌شده را بزند، `canonicalLabel()` آن را به کلید اصلی نگاشت می‌کند ( پس افزودن دکمهٔ جدید هم مسیرها را نمی‌شکند).
- ترجمهٔ هر کلید از پنل قابل تغییر است: **پنل ← تنظیمات ← 🌐 ترجمه‌ها** (ذخیره با کلید `i18n:<lang>:<key>`) و متن‌های بات با `text:<key>:<lang>`.
- `lang_default` و `lang_ask` (روشن/خاموش بودن پرسش زبان) از پنل تنظیم می‌شوند.

### 🧪 پست/متن/دکمهٔ شیشه‌ای (استودیو)
- از ربات: **`/glass`** یا دکمهٔ «🧪 پست شیشه‌ای» — عنوان، متن، تا `glass_max_buttons` دکمه (متن + لینک)، شش استایل (اورورا، نئون، مینیمال، سلطنتی، دارک، آبنباتی) و عکس اختیاری.
- هر پست یک **کد ۵ رقمی** می‌گیرد. راه‌های انتشار (هر سه واقعی):
  1. `@BotName <کد>` در هر گروه یا چت → کارت شیشه‌ای اینلاين (با لینک و متن؛ تلگرام روی نتیجهٔ اینلاين `reply_markup` نمی‌پذیرد، پس لینک در متن می‌آید).
  2. فوروارد کردن پیام خودِ ربات → **دکمه‌های شیشه‌ای زنده** می‌مانند.
  3. **`/glass post <کد>`** (یا `/glass post <کد> @channel`) → ربات پست را با کیبورد شیشه‌ای در همان چت منتشر می‌کند؛ با `glass_auto_post=1`، انتخاب نتیجهٔ اینلاين (`chosen_inline_result`) خودش پست می‌کند.
- صفحهٔ وب هر پست: **`/g/<کد>`** (آمار بازدید/کلیک، دکمه‌ها، RTL) — با `glass_web_enabled` قابل خاموش‌کردن.
- **استودیوی وب شیشه‌ای**: لینک امن و امضاشده (`/g/studio/<uid>/<sig>`، HMAC با توکن بات) برای ساخت/ویرایش سریع پست، به‌علاوهٔ API داخل مینی‌اپ (`/api/glass/*`).
- **پست دعوت شیشه‌ای** برای هر کاربر (`👥 پست دعوت شیشه‌ای من`) که با `?start=ref_ID` زیرمجموعه می‌آورد.
- هر کلیک/بازدید در `glass_stats` ثبت می‌شود؛ محدودیت روزانه `glass_daily_limit` و انتشار عمومی با `glass_public`.

### 🧪 نسخهٔ شیشه‌ایِ کانفیگ‌ساز
- ویزارد **کانفیگ‌ساز اختصاصی** حرفه‌ای‌تر شد: پروتکل (VLESS+Reality، Trojan:443، Shadowsocks، WS+CDN)، مدت ۱۴ تا ۳۶۵ روز، حجم ۲۵ تا نامحدود، **نوار قدم‌ها** و قاب شیشه‌ای هم‌رنگ استایل انتخابی ادمین، پیش‌نمایش قیمت لحظه‌ای + کوپن شخصی.
- هر اشتراک یک **صفحهٔ شیشه‌ای اختصاصی** دارد: `/sub/<توکن>/card` (یا `/sc/<توکن>`) با QR، کپی لینک، شمارندهٔ اعتبار، تعداد دستگاه و دکمهٔ «اشتراک در گروه».
- دکمهٔ **«📣 پست برای گروه‌ها»** در «🧩 اشتراک‌های من» و کنار QR — پست شیشه‌ایِ کانفیگ می‌سازد و کد انتشار می‌دهد (بدون افشای لینک واقعی در گروه).
- نمونهٔ زندهٔ صفحه قبل از خرید: `/sc/demo` (با برچسب «نمونهٔ نمایشی» — هیچ کانفیگ واقعی‌ای نشان نمی‌دهد).

### 🛍 خرید کانفیگ داخل گروه (checkout گروهی)

- **ضدسوءاستفاده رفرال**: یوزرنیم یکسان با معرف یا خوشهٔ حساب‌های هم‌نام از یک معرف (`ref_max_same_name`) → پاداش رد و در `users.ref_blocked` ثبت می‌شود.

### 👑 ابزارهای مالک (از پنل و از ربات)
- **گزارش فروش روزانه/هفتگی** خودکار (`report_enabled`، `report_hour_utc`) در ساعت تنظیمی + دکمهٔ «📊 گزارش» در پنل.
- **پیام همگانی زمان‌بندی‌شده**: از ربات (`adm:bclist`) یا پنل؛ در صف می‌نشیند و کرون هر `broadcast_batch` کاربر (پیش‌فرض ۲۵) را ارسال می‌کند، با حذف تکراری‌ها و لغو/پاکسازی.
- **تولید انبوه کد تخفیف**، **لاگ بازرسی** (`audit_log` برای اقدامات ادمین و پنل)، **پشتیبان JSON** کامل (`/api/panel/backup/json`) با **ماس‌کردن خودکار** توکن/رمز/سکرت و جدول `settings`.
- قفل کانال (`channel_lock`)، موجودی انبار، و تنظیم هر کدام از قابلیت‌های بالا از **پنل ← 🧪 پست/جوایز**.

### 🕐 کرون‌جاب‌های اضافه‌شده
`broadcastTick` (صف پیام همگانی) و `reportTick` (گزارش فروش) به چرخهٔ هر ۱۵ دقیقه اضافه شدند؛ هر دو اگر خاموش باشند هیچ هزینه‌ای ندارند.

## ✅ چک‌لیست بعد از دیپلوی (دو قدم، بدون کدنویسی)

1. **`/setup`** در مرورگر (آدرس Worker) → فقط **توکن ربات** و **رمز پنل (۱۰ رقم)** را وارد کنید؛ بقیهٔ کلیدها (HMAC، سشن، کلید استودیو) تصادفی ساخته می‌شوند و پرسیده نمی‌شوند.
2. در تلگرام **`/start`** → اولین نفر با رمز پنل، **مالک/سوپرادمین** ثبت می‌شود (قفل ۵ تلاش). از اینجا به بعد همه‌چیز از **پنل وب** یا **`/admin`** تنظیم می‌شود.

نکات عملی که واقعاً فرق می‌کنند (بی‌تعارف):

- **`@BotName 31763` در گروه**: این روش اینلاين است و با حالت خصوصی معمولی (privacy mode) هم کار می‌کند — نیازی به تغییر تنظیمات نیست؛ اما کارت اینلاين طبق محدودیت API تلگرام **دکمهٔ شیشه‌ای زنده ندارد** (لینک در متن می‌آید). برای دکمهٔ زنده: فوروارد پیام ربات، یا **`/glass post <کد>`**، یا `glass_auto_post=1`.
- **خرید/فیش در گروه**: برای اینکه ربات عکس فیش و پیام‌های عادی را در گروه ببیند، یا ربات را **ادمین گروه** کنید یا حالت privacy بات را در BotFather خاموش کنید (`/setprivacy` → Disable). دستورات مثل `/buy` همیشه می‌رسند.
- **سرورها**: تا وقتی از پنل سرور واقعی وارد نکرده‌اید، خرید و تحویل **قفل** است و پولی کم نمی‌شود — هیچ کانفیگ نمونه‌ای ساخته و فروخته نمی‌شود.
- **نرخ تتر/طلا**: از میانهٔ منابع واقعی گرفته می‌شود؛ اگر همهٔ منابع قطع باشند، عدد جعلی نمی‌گویید — **نرخ دستی** در پنل بگذارید.
- **تضمین ۱۰۰٪ آپ‌تایم نمی‌دهیم**: به‌جایش کرون سلامت سرور، جایگزینی خودکار کانفیگ مرده (حداقل ۱۰ کانفیگ در هر ساب) و kill-switch داریم.
- **پنل مدیریت فارسی است** (طبق درخواست)؛ ترجمه‌ها فقط برای کاربران ربات: ۵ زبان fa/en/ar/ru/tr.

## 🔐 نکته امنیتی

- توکن ربات، رمز پنل، کلید API درگاه و مرچنت‌آیدی فقط در **D1/Durable Object همین ورکر شما** ذخیره می‌شوند؛ هیچ‌کدام در ریپو، `wrangler.toml` یا پاسخ API برنمی‌گردند (پنل وب آن‌ها را ماسک‌شده نشان می‌دهد و مسیر `/api/panel/settings` اجازهٔ نوشتن/خواندن کلیدهای حساس را ندارد).
- رمز پنل وب **دقیقاً ۱۰ رقم عددی** است (هم در `/setup`، هم در ربات، هم در پنل وب اعتبارسنجی می‌شود) و اگر نسازید، تصادفی ساخته می‌شود.
- ورود به پنل وب با کوکی HttpOnly + SameSite=Lax است و سشن در KV/DO با TTL می‌میرد؛ `/setup` بعد از راه‌اندازی، توکن را دوباره نمی‌نویسد و پیام ۴۰۹ می‌دهد.
- امضای HMAC روی callback درگاه و اعتبارسنجی `initData` تلگرام در مینی‌اپ/پروب، جعل درخواست را مسدود می‌کند؛ تحویل سرویس فقط بعد از وریفای سرور‌به‌سرور انجام می‌شود.

توکن بات در این ریپازیتوری قرار نمی‌گیرد. در تولید آن را فقط از `/setup` وارد کنید تا داخل Durable Object همان Worker ذخیره شود؛ برای توسعه محلی نیز فقط از فایل ignored به نام `.dev.vars` استفاده کنید. اگر یک نصب قدیمی Secret محیطی داشته باشد، آن مقدار فقط fallback است و مقدار ذخیره‌شده در Durable Object اولویت دارد.
